# AGENTS.md — инструкция для ИИ-исполнителя

Ты разрабатываешь мобильное приложение **«Что приготовить?»** (Flutter, Android). Этот файл — точка входа: прочитай его целиком, затем файлы из раздела «Что читать», и только потом пиши код.

## Что строим (коротко)

Бабушка отмечает продукты, которые есть дома, и получает блюда, которые из них можно приготовить: с типом (суп, второе, десерт…), сложностью, рецептом и пошаговым режимом готовки. ИИ придумывает новые блюда, не повторяется и учитывает вкусы. Есть календарь блюд на месяц и история приготовленного.

ИИ работает в двух режимах:
1. **LM Studio на домашнем ПК** — если телефон в Wi-Fi и приложение нашло ПК в локальной сети (основной режим).
2. **GigaChat API** — если ПК не найден или не ответил (запасной режим).
3. Если нет ни того ни другого — приложение работает на встроенном каталоге рецептов, без ошибок на экране.

## Жёсткие правила

1. **Работай по этапам из `docs/TASKS.md` строго по порядку.** Не начинай этап N+1, пока этап N не закрыт.
2. **Задача не считается сделанной без доказательства.** К отчёту прикладывается вывод `tool/check.ps1` (analyze + test), выполненного **после последней правки**. Слова «должно работать» не принимаются.
3. **Не выдумывай API.** Эндпоинты LM Studio и GigaChat — в `skills/ai-integration`. Чего там нет — сверься с официальной документацией и укажи ссылку в отчёте.
4. **Неясно — не угадывай молча.** Выбери самый простой вариант, пометь в коде `// ASSUMPTION: ...` и добавь строку в `docs/DECISIONS.md`.
5. **Приоритет источников:** `docs/DECISIONS.md` (принятые решения) > `docs/TASKS.md` > `docs/TZ.md` > скиллы. При противоречии действует более приоритетный.
6. **Не меняй спецификацию сам.** Если ТЗ противоречиво или невыполнимо — запиши вопрос в `docs/STATUS.md` → «Вопросы владельцу» и переходи к следующей независимой задаче.
7. **Секреты не в коде.** Ключ GigaChat — только `flutter_secure_storage`. Никаких ключей в репозитории, логах, тестах, fixtures.
8. **Язык:** код, идентификаторы, комментарии — английский. Тексты интерфейса — русский, через ARB-файлы (`lib/l10n/app_ru.arb`).
9. **Тесты обязательны** для: нормализации продуктов, скоринга, антиповторов, профиля вкусов, `RecipeValidator`, `AiRouter`, правил календаря.
10. **Не ломай офлайн.** Любая фича, которой нужен ИИ, обязана иметь путь без ИИ.
11. **Маленькие шаги.** Один коммит — одна задача из `TASKS.md`, сообщение вида `S3-04: AiRouter fallback to GigaChat`.

## Параметры проекта

- Папка проекта: `C:\dev\cooker` (без пробелов и кириллицы — так и оставь).
- Создание: `flutter create --org dev.chtoprigotovit --project-name chto_prigotovit --platforms=android .`
  `flutter create` в непустой папке не перезаписывает уже лежащие файлы — `analysis_options.yaml` и `.gitignore` отсюда сохранятся.
- Android: `minSdk 24`, `targetSdk` — по умолчанию текущего Flutter stable.
- Структура `lib/` — раздел 3 ТЗ.

## Формат отчёта по этапу

Шаблон — `docs/REPORT_TEMPLATE.md`. Файл: `docs/reports/STAGE_<N>.md`. Внутри обязательно: что сделано по ID задач, как запустить, вывод проверок, скриншоты (путь к файлам в `docs/reports/img/`), что не готово, новые ASSUMPTION.

## Если застрял

- Ошибка сборки Android/Gradle/NDK → `docs/ENV_SETUP.md`, раздел «Известные проблемы».
- Две попытки одного и того же исправления не помогли → остановись, опиши проблему в `docs/STATUS.md` (что пробовал, точный текст ошибки) и переходи к другой задаче.
