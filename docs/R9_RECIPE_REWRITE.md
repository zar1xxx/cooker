# R9. Переписывание шаблонных рецептов

Автор плана: Claude, 2026-11-10. Исполнитель: локальный агент. Решение владельца: шаблонные рецепты переписываются на настоящие, партиями, с приоритетом самых частых блюд.

## 0. Проблема
В `assets/seed/recipes.json` 2039 рецептов, но около 1590 собраны по шаблону:
- шаги повторяются сотнями раз («Замесите мягкое эластичное тесто…» — 180 раз, «Сформируйте изделие…» — 180 раз);
- описания одинаковые («Аппетитное блюдо из рыбы и морепродуктов…» — 187 раз);
- 1489 рецептов имеют ровно 4 шага;
- 17 рецептов с сырым мясом/рыбой/яйцами не имеют шага с таймером.
Хорошие 125 исходных рецептов (из `tool/seed_data/*.dart`) и часть агентских рецептов — настоящие. Их не трогать.

## 1. Правила работы (главное)
1. **Каждый рецепт пишется отдельно, по смыслу названия.** Запрещено: генераторы с шаблонами, подстановка названия продукта в общую фразу, копирование шага из другого рецепта с заменой слова, любые скрипты, которые сами составляют текст шагов. Скрипты допустимы только для проверки, чтения и записи JSON.
2. Шаги называют реальные действия, температуру, время, признак готовности («до золотистой корочки», «пока лук не станет прозрачным»), порядок закладки продуктов. Минимум 4 шага для простых блюд, 5–8 для остальных.
3. Описание — 1–2 предложения именно об этом блюде (вкус, подача, повод), не общая фраза про категорию.
4. Нельзя менять `id`, `title`, `dish_type`, `dish_group`, `cuisine`, список `ingredients` (id и количества). Если ингредиентов явно не хватает для реального рецепта — не придумывать новые id, а записать рецепт в `docs/reports/rewrite/needs_ingredients.md` (id, чего не хватает) и пропустить.
5. Масла, соль, перец, вода: если в шаге нужны, они должны быть в `ingredients`; если их нет — не упоминать количество в шаге.
6. Таймеры: `timer_seconds` ставить у каждого шага с ожиданием (варка, запекание, расстойка, маринование, остывание). Сырое мясо, птица, рыба, яйца, фарш — обязателен шаг с температурой/временем термообработки и признаком готовности.
7. `total_minutes`, `active_minutes`, `cook_minutes` должны соответствовать шагам (сумма таймеров не больше `total_minutes`). Если по шагам время другое — исправить числа.
8. `kcal_per_serving` не выдумывать заново, если оно правдоподобно; если очевидно неверно (суп 900 ккал, салат 20 ккал) — пересчитать оценкой по ингредиентам и записать в отчёт.
9. `difficulty` не править руками: после пакета запускается `dart run tool/recalculate_recipe_difficulty.dart`.
10. Язык: русский, обращение «вы» в повелительном наклонении («Нарежьте…»), без канцелярита и без англицизмов. Единицы как в приложении (г, мл, ст. л., ч. л., шт.).
11. Безопасность — по skills/recipe-safety (аллергены, термообработка, количества). Любой спорный рецепт (сырые яйца, сыроедение, консервирование) — в `docs/reports/rewrite/needs_review.md`, владелец решит.

## 2. Подготовка (один раз)
**R9-01. Детектор шаблонности.** `tool/detect_templated_recipes.dart`:
- Читает `assets/seed/recipes.json`.
- Шаблонным считает рецепт, если выполнено любое: (a) хотя бы 2 его шага встречаются (по первым 40 символам) в 10 и более других рецептах; (b) описание встречается в 10 и более рецептах; (c) нет ни одного шага с уникальным текстом.
- Выводит `docs/reports/rewrite/templated.csv` (id, title, dish_type, причины) и сводку по dish_type.
- Тест `test/detect_templated_test.dart` на 3 заведомо шаблонных и 3 заведомо хороших рецептах.

**R9-02. Поле качества.** В `assets/seed/recipes.json` добавить рецептам поле `"quality": "template" | "curated"` (по умолчанию `"curated"` для нешаблонных). Миграция БД: колонка `quality` (drift, schemaVersion +1, миграция по skills/drift-database, тест миграции). `RecipeValidator` и `validate_seed.dart` учитывают поле (допустимые значения; для `curated` — условия из раздела 3).

**R9-03. Приоритеты.** `tool/rank_rewrite_queue.dart` строит `docs/reports/rewrite/queue.csv` — очередь переписывания:
1. Блюда, часто встречающиеся в запросах помощника и в лентах (если данных нет — по частоте «народности»: борщ, щи, пельмени, блины, котлеты, плов, запеканки, омлеты, салаты оливье/винегрет и т. д.; агент составляет список из 150 самых известных блюд сам и кладёт в `tool/seed_data/priority_dishes.csv`).
2. Затем остальные по порядку dish_type: main, soup, breakfast, salad, side, baking, dessert, snack, drink, preserve.
3. Внутри очереди — по возрастанию `id`.

**R9-04. Лента: порядок и плашка.** В ранжировании ленты (R8-08) рецепты `quality = curated` получают бонус, шаблонные идут ниже, но не скрываются. В карточке шаблонного рецепта показывается пометка «Упрощённая карточка» (оформление по skills/senior-ux, нажатие раскрывает пояснение: «Шаги для этого блюда описаны кратко»). Тесты: порядок ленты, виджет-тест пометки. Эта задача делается ДО массового переписывания, чтобы приложение уже выглядело честно.

## 3. Конвейер переписывания (повторяется партиями)
Размер партии — **20 рецептов** одного dish_type из очереди. Для каждой партии:

1. Взять 20 следующих id из `queue.csv`, у которых `quality = template`.
2. Прочитать каждый рецепт (ингредиенты с количествами, время, порции, название).
3. Написать для каждого новые `description` и `steps` (правила раздела 1). Результат — файл `tool/seed_data/rewrite/batch_NNN.json` вида `{"recipes":[{"id":...,"description":"...","steps":[{"text":"...","timer_seconds":600}]}]}`. Только эти поля (плюс исправленные `total_minutes` / `active_minutes` / `cook_minutes` / `kcal_per_serving`, если нужно).
4. Применить: `dart run tool/apply_rewrite_batch.dart tool/seed_data/rewrite/batch_NNN.json`. Скрипт (написать один раз, R9-05): подменяет только разрешённые поля по id, ставит `quality = "curated"`, отказывается применять, если пакет содержит запрещённые поля, неизвестный id или шаг короче 20 символов.
5. `dart run tool/recalculate_recipe_difficulty.dart`, затем `dart run tool/validate_seed.dart`.
6. Проверка новых рецептов автопроверкой `tool/lint_curated_recipes.dart` (R9-05):
   - каждый шаг ≥ 20 символов;
   - шаги внутри рецепта не повторяются;
   - ни один шаг не встречается более чем в 3 рецептах всего каталога (иначе это снова шаблон);
   - описание уникально в каталоге;
   - у рецептов с сырым мясом/птицей/рыбой/яйцами/фаршем есть шаг с `timer_seconds`;
   - `sum(timer_seconds)/60 ≤ total_minutes`;
   - все числа/единицы в шагах не противоречат ингредиентам (если в шаге «2 яйца», в ингредиентах яиц ≥ 2).
7. Если автопроверка красная — исправить текст партии, а не ослаблять проверку.
8. Коммит: `R9-NN: переписано 20 рецептов (batch_NNN, dish_type)`. Один пакет — один коммит.

**Контрольные точки** (после каждых 100 переписанных рецептов, то есть каждые 5 партий):
- `tool\check.ps1` — GREEN (число тестов брать из свежего `last_check.txt`).
- Выборка для владельца: `docs/reports/rewrite/sample_NNN.md` — 5 случайных переписанных рецептов целиком (название, ингредиенты, шаги, время). Формат такой же, как у `gen/sample_N.md`.
- Обновить `docs/reports/rewrite/PROGRESS.md`: переписано N из ~1590, осталось M, по dish_type, список пропущенных (needs_ingredients / needs_review).
- Остановиться и ждать ответа владельца на выборку (если ответа нет — продолжать по очереди, исправления вносить потом отдельным коммитом).

## 4. Устойчивость к лимитам
Агент уже один раз остановился из-за лимитов. Поэтому:
- Состояние хранится в файлах, а не в памяти: `queue.csv`, `PROGRESS.md`, `batch_NNN.json`. В начале сессии агент читает `PROGRESS.md` и продолжает со следующей партии.
- После каждой партии `PROGRESS.md` обновляется и коммитится. Недописанная партия не применяется: либо все 20 рецептов пакета проходят проверки, либо файл остаётся в `tool/seed_data/rewrite/pending/`.
- Не хватило лимита — оставить в `PROGRESS.md` строку «остановлен после batch_NNN» и закончить. Не писать заглушки, чтобы закончить.

## 5. Объём и порядок работ
- ~1590 рецептов / 20 = ~80 партий. Это много; цель первого захода — **первые 300 рецептов (15 партий)**, начиная с `priority_dishes.csv`, затем контрольная точка и решение владельца о продолжении.
- Порядок: R9-01 → R9-02 → R9-04 → R9-03 → R9-05 → партии 1–5 → контрольная точка → партии 6–15 → отчёт.
- Рецепты с `quality = template` остаются в приложении (лента, подбор по продуктам), но помечены.

## 6. Приёмка (для проверки мной и владельцем)
- [ ] `check.ps1` GREEN после каждой контрольной точки.
- [ ] `lint_curated_recipes.dart` зелёный для всех `curated`.
- [ ] В `recipes.json` нет `curated` рецептов с шагом, который встречается в более чем 3 рецептах.
- [ ] Сложность пересчитана, распределение не «всё easy» (проверить по сводке в PROGRESS.md).
- [ ] Выборки sample_NNN.md просмотрены владельцем (задача A2).
- [ ] В отчёте указано: сколько переписано, сколько пропущено и почему.
- [ ] Отчёт содержит только то, что подтверждено файлами: число из `recipes.json`, а не «по моим подсчётам».

## 7. Что нельзя
- Генерировать рецепты пакетным шаблонным скриптом (в том числе «умным», с подстановкой слов).
- Подгонять проверки под свои тексты.
- Менять `connect_phone.*`, `create_desktop_shortcut.*`, git push/pull/merge/rebase, класть ключи в репозиторий.
- Писать в отчёт результаты, которых нет в сохранённых файлах.
