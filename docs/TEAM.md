# Команда и правила совместной работы

- **Даниил** — владелец, принимает решения, сливает изменения в `master`.
- **ИИ-агент** — пишет основной код по `docs/TASKS.md`, работает в локальной папке Даниила.
- **Август** — помогает: проверка на телефоне, данные, дизайн, отдельные модули (список ниже).

## Правила для Августа

1. **Ветки.** Никаких коммитов в `master`. Каждая задача — своя ветка `august/<номер>-<кратко>` (например `august/A3-holidays`) и Pull Request в `master`. Сливает Даниил.
2. **Только свои файлы.** У каждой задачи ниже указано, какие файлы можно создавать и менять. Остальное не трогать, особенно `lib/` вне своих файлов, `docs/TASKS.md`, `docs/STATUS.md`, `docs/DECISIONS.md`, `AGENTS.md`, `skills/` — их ведёт агент и Даниил. Хочешь изменить что-то за пределами задачи — заведи Issue.
3. **Баги и идеи — в Issues** на GitHub: что делал, что ждал, что получилось, скриншот, модель телефона, версия APK. Метки: `bug`, `idea`, `content`, `design`.
4. **Проверки.** Перед PR с кодом: `tool\check.ps1` должен быть зелёным, вывод (последние 20 строк) — в описание PR. Для данных (JSON/CSV) — прогон проверочного скрипта задачи.
5. **Секреты.** Никаких ключей GigaChat, паролей, `key.properties`, `.env` в репозитории, в Issues и в PR.
6. **Тексты рецептов и картинки** — только свои или с открытой лицензией (указать источник и лицензию в PR). Не копировать рецепты и фото с сайтов.
7. **Стиль.** Код и комментарии — по-английски, тексты интерфейса — по-русски через `lib/l10n/app_ru.arb`. Перед работой над экраном прочитать `skills/senior-ux/SKILL.md` (два режима: «Просто» и «Полный»).

## Как Даниилу сливать работу Августа без конфликтов с агентом

1. Перед слиянием PR закоммитить и отправить текущую работу агента (GitHub Desktop: Commit → Push).
2. Слить PR Августа на GitHub.
3. Забрать изменения локально (GitHub Desktop: Fetch → Pull) **до** следующей сессии агента.
4. Сказать агенту: «подтянуты изменения Августа из PR №…, учти их».

- Результат: Issues с метками `bug` / `idea`. **Файлы:** не меняет.

### A2. Проверка контента рецептов (без кода)
- Читать выборки `docs/reports/gen/sample_N.md`, которые агент создаёт при генерации 2000 рецептов (R8-09).
- Отмечать: странные пропорции, неправильное время или сложность, опасное (сырое мясо без обработки, аллергены не отмечены), повторы, неестественный язык.
- Результат: один Issue на выборку с меткой `content`, список номеров рецептов и замечаний. **Файлы:** не меняет.

### A3. Праздники и посты — `HolidayCalculator` (код, отдельный модуль)
Это часть R7-03, агент её сейчас не делает.
- Чистый Dart без Flutter: `lib/core/calendar/holiday_calculator.dart`, данные `assets/seed/holidays_ru.json`, тесты `test/holiday_calculator_test.dart`.
- Правила — из `docs/reports/R7_RESEARCH.md`: государственные праздники (ст. 112 ТК РФ), православная Пасха (алгоритм Гаусса, юлианский календарь + 13 дней), мясопустное воскресенье P−56 отдельным днём, Масленица P−55…P−49, Великий пост P−48…P−1, Вербное P−7, Троица P+49, Петров пост P+57…11 июля, Успенский 14–27 августа, Рождественский 28 ноября – 6 января.
- API: `List<Occasion> occasionsOn(DateTime date)` и `Occasion? nextOccasion(DateTime from, {int windowDays = 3})`; у `Occasion`: код, название, тип (`holiday`/`fast`/`feast`), кулинарная подсказка («блины», «без мяса»).
- Тесты: Пасха 2024–2030 сверить с официальным календарём, високосный год, переход через Новый год для Рождественского поста.
- **Файлы:** только перечисленные выше. Агент потом подключит модуль в R7-03.

### A4. Справочник продуктов для «нажми и узнай» (данные)
Нужен для R8-13 (нижний лист продукта). Агент сделает экран, а данные — Август.
- Новый файл `assets/seed/ingredient_info.json`: для каждого `id` из `assets/seed/ingredients.json` — где хранить, сколько хранится (дни), чем заменить (id других продуктов), короткий совет (1 фраза). Формат:
  ```json
  {"potato": {"storage": "pantry", "shelf_days": 60, "substitutes": ["sweet_potato"], "tip": "Хранить в тёмном прохладном месте, отдельно от лука."}}
  ```
  `storage`: `fridge` / `freezer` / `pantry`.
- Сначала 100 самых частых продуктов, потом остальные.
- Проверка: маленький скрипт `tool/validate_ingredient_info.dart` — все id существуют, замены тоже существуют, нет пустых полей.
- **Файлы:** только `assets/seed/ingredient_info.json` и `tool/validate_ingredient_info.dart`. Если файла нет или он неполный, агент показывает только базовую информацию.
