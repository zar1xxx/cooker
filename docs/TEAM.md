# Команда и правила совместной работы

- **Даниил** — владелец, принимает решения, сливает изменения в `master`.
- **ИИ-агент** — пишет основной код по `docs/TASKS.md`, работает в локальной папке Даниила.
- **Август** — друг, помогает по возможности. **С 2026-11-09 на паузе**: приступит позже, его задачи временно переданы Даниилу и агенту (см. ниже). Когда вернётся — задачи можно отдавать обратно.

## Правила для Августа

1. **Ветки.** Никаких коммитов в `master`. Каждая задача — своя ветка `august/<номер>-<кратко>` (например `august/A3-holidays`) и Pull Request в `master`. Сливает Даниил.
2. **Только свои файлы.** У каждой задачи ниже указано, какие файлы можно создавать и менять. Остальное не трогать, особенно `lib/` вне своих файлов, `docs/TASKS.md`, `docs/STATUS.md`, `docs/DECISIONS.md`, `AGENTS.md`, `skills/` — их ведёт агент и Даниил. Хочешь изменить что-то за пределами задачи — заведи Issue.
3. **Баги и идеи — в Issues** на GitHub: что делал, что ждал, что получилось, скриншот, модель телефона, версия APK. Метки: `bug`, `idea`, `content`, `design`.
4. **Проверки.** Перед PR с кодом: `tool\check.ps1` должен быть зелёным, вывод (последние 20 строк) — в описание PR. Для данных (JSON/CSV) — прогон проверочного скрипта задачи.
5. **Секреты.** Никаких ключей GigaChat, паролей, `key.properties`, `.env` в репозитории, в Issues и в PR.
6. **Тексты рецептов и картинки** — только свои или с открытой лицензией (указать источник и лицензию в PR). Не копировать рецепты и фото с сайтов.
7. **Стиль.** Код и комментарии — по-английски, тексты интерфейса — по-русски через `lib/l10n/app_ru.arb`. Перед работой над экраном прочитать `skills/senior-ux/SKILL.md` (два режима: «Просто» и «Полный»).

## Как Даниилу сливать работу Августа без конфликтов с агентом

1. Перед слиянием PR закоммитить и отправить текущую работу агента (GitHub Desktop: Commit → Push).
2. Слить PR Августа на GitHub.
3. Забрать изменения локально (GitHub Desktop: Fetch → Pull) **до** следующей сессии агента.
4. Сказать агенту: «подтянуты изменения Августа из PR №…, учти их».

## Задачи A1–A7 (раньше предназначались Августу, сейчас переданы)

Статус: **Август на паузе**. Каждая задача теперь закреплена за Даниилом или за агентом. Если Август вернётся, любую незакрытую задачу можно передать ему обратно: тогда правила выше (ветки, свои файлы, Issues) снова действуют.

### Задачи Даниила (нужен телефон и решения владельца)

**A1. Проверка на своём телефоне (постоянно).**
- Ставить каждый новый APK, проходить сценарии из `docs/R8_PLAN.md` (S8-01…S8-13) и `docs/TZ.md` раздел 11.
- Проверять оба режима интерфейса, крупный шрифт системы, тёмную тему.
- Результат: замечания агенту с скриншотами (файлы в `docs/reports/img/device/`), либо Issues на GitHub, если удобнее.

**A2. Просмотр выборок рецептов.**
- Читать `docs/reports/gen/sample_N.md`, которые агент создаёт при генерации 2000 рецептов (R8-09): странные пропорции, неверное время или сложность, опасное (сырое мясо без обработки, аллергены не отмечены), повторы, неестественный язык.
- Результат: список номеров рецептов и замечаний агенту. Достаточно просмотреть первую выборку и затем по одной на каждые 500.

**A6-часть. Данные для магазина приложений, которые знает только владелец.**
- Название приложения, имя разработчика, контактная почта для магазина, согласие с политикой конфиденциальности. Агент подготовит тексты, Даниил проверит и утвердит (см. A6 ниже).

**A7. Проверка ссылки Купера (5 минут).**
- На телефоне с установленным приложением «Купер» открыть `https://kuper.ru/search?query=молоко`: открывается приложение или браузер? Работает ли поиск без входа в аккаунт?
- Результат: ответ агенту одной строкой или запись в STATUS.md → «Ответы владельца» (пункт 6 из «Проверить владельцу»).

### Задачи агента (вместо Августа)

Выполняются **после** основной очереди R8 (первая и вторая контрольные точки), если владелец не поставил иначе. Каждая задача — отдельным коммитом по правилу 11.

**A3. Праздники и посты — `HolidayCalculator` (часть R7-03).**
- Чистый Dart без Flutter: `lib/core/calendar/holiday_calculator.dart`, данные `assets/seed/holidays_ru.json`, тесты `test/holiday_calculator_test.dart`.
- Правила — из `docs/reports/R7_RESEARCH.md`: государственные праздники (ст. 112 ТК РФ), православная Пасха (алгоритм Гаусса, +13 дней), мясопустное воскресенье P−56 отдельным днём, Масленица P−55…P−49, Великий пост P−48…P−1, Вербное P−7, Троица P+49, Петров пост P+57…11 июля, Успенский 14–27 августа, Рождественский 28 ноября – 6 января.
- API: `List<Occasion> occasionsOn(DateTime date)` и `Occasion? nextOccasion(DateTime from, {int windowDays = 3})`; у `Occasion`: код, название, тип (`holiday`/`fast`/`feast`), кулинарная подсказка.
- Тесты: Пасха 2024–2030 сверить с календарём на patriarchia.ru (ссылку в отчёт), високосный год, переход через Новый год для Рождественского поста.

**A4. Справочник продуктов для «нажми и узнай» (R8-13).**
- `assets/seed/ingredient_info.json`: для каждого `id` из `ingredients.json` — `storage` (`fridge`/`freezer`/`pantry`), `shelf_days`, `substitutes` (id), `tip` (1 фраза). Сначала 100 самых частых продуктов, потом остальные.
- Скрипт проверки `tool/validate_ingredient_info.dart`: все id существуют, замены существуют, нет пустых полей. Сроки хранения брать из общепринятых рекомендаций, спорные пометить `"approx": true`.

**A5. Иконки разделов и плашки «От помощника».**
- 11 SVG-иконок разделов блюд + иконка плашки «От помощника» в `assets/images/sections/` и `assets/images/badges/`, один стиль, читаются в светлой и тёмной теме, понятны без подписи. Рисует агент сам (оригинальные, без чужих значков), список в `assets/images/README.md`.

**A6. Материалы для магазина приложений.**
- Тексты в `docs/store/`: описание (короткое до 80 символов и полное), ключевые слова, политика конфиденциальности простыми словами (данные на телефоне, на ПК/GigaChat уходят только продукты и предпочтения без имени), чек-лист публикации RuStore/Google Play.
- Скриншоты из эмулятора или golden-тестов в обоих режимах; иконка 512×512 — оригинальная, без чужой графики.
- Поля, которые знает только владелец (название аккаунта разработчика, почта), оставить с пометкой `TODO(owner)`.
