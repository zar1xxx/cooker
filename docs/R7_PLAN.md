# R7. Лента «Может понравиться», разделы и подбор продуктов

Источник идей: Август Теске. Статус: план, к выполнению после проверки R6 на телефоне.
Правила те же: AGENTS.md, скиллы senior-ux, recipe-safety, ai-integration, drift-database. В отчёт идёт только вывод, сохранённый в файл.

## Принципы
1. Подбор ленты считает **локальный алгоритм** (быстро, без сети, объяснимо). ИИ нужен только чтобы придумать блюда, которых нет в каталоге, и объяснить выбор одной фразой.
2. Любое блюдо от ИИ проходит RecipeValidator (аллергены, тепловая обработка, количества). Блюда с аллергенами пользователя в ленту не попадают никогда.
3. Интерфейс для бабушки: максимум 5 горизонтальных лент на экране, крупные карточки, один главный выбор. Остальное в «Ещё».
4. Доставка: никакого парсинга сайтов и обхода защиты. Только официальные способы (ссылка, поиск, список для отправки).

## R7-01. Таксономия блюд (как «царства»)
Ввести три независимых измерения. Одно блюдо = один раздел + любое число тегов.
- **Раздел (dish_group), ровно один:** выпечка, мясные, рыбные и морепродукты, овощные, супы, каши и гарниры, салаты и закуски, яйца и молочное, десерты, напитки, заготовки.
- **Диетические теги:** вегетарианское, веганское, постное, малокалорийное (порог ккал на порцию в константе), без глютена, без лактозы, высокобелковое.
- **Кухня (cuisine):** код страны (ru, it, ge, uz, fr, cn, jp, tr и т. д.) или `home`.
- **Поводы (occasion):** повседневное, праздничное, быстрое (до 30 мин), для гостей, на природу, детям.
- **Настроение (mood):** уютное, лёгкое, сытное, хочется нового, по-быстрому, порадовать себя.
Задачи: enum и константы в `lib/core/catalog/`, правила вывода тегов из состава (мясо в ингредиентах → не вегетарианское; ккал из справочника), юнит-тесты на каждое правило.

## R7-02. База данных (drift, миграция)
- В recipes: `dish_group`, `cuisine`, `kcal_per_serving`, `cook_minutes`, `source` (seed / ai / user).
- Таблицы связей `recipe_tags(recipe_id, tag_kind, tag)`.
- `feed_events(recipe_id, event, context_json, at)`: показан, открыт, приготовлен, пропущен («не хочу»), оценка 1–5.
- Миграция со schemaVersion+1, тест миграции со старой базы, кодогенерация, проверка через flutter-checks.
- Разметить seed-рецепты (assets/seed/recipes.json) группой, кухней, тегами. Проверка скриптом: у каждого рецепта есть группа и кухня.

## R7-03. Контекст дня (`DayContext`)
Класс, собирающий вход для ленты, без сети:
- дата, день недели, время суток, сезон;
- ближайший повод из офлайн-календаря (`assets/seed/holidays_ru.json` + расчёт Пасхи и Масленицы по алгоритму, посты, День Победы, Новый год, 8 марта и т. д.), окно «за 0–3 дня до»;
- настроение, выбранное вручную (по умолчанию пусто);
- выбранная кухня мира, если есть;
- продукты дома.
Тесты на фиксированные даты, включая високосный год и плавающие праздники.

## R7-04. Профиль вкуса
`TasteProfile` строится из feed_events и существующих настроек вкуса:
- вес по разделам, кухням, тегам и ключевым ингредиентам: приготовил / оценка ≥4 → плюс, пропустил / оценка ≤2 → минус;
- затухание по времени (полураспад 60 дней), чтобы вкус мог меняться;
- жёсткие запреты: аллергены, нелюбимые продукты, постные дни, если включены. Это фильтр до подсчёта очков.
- холодный старт: пока событий меньше 10, профиль берётся из анкеты вкусов и общей популярности seed-рецептов.

## R7-05. Алгоритм ленты `FeedRanker`
Чистый Dart, без Flutter и сети, детерминированный при фиксированном seed.
1. **Фильтр:** убрать аллергены, нелюбимое, блюда из окна «не повторять» (приготовленные за последние 14 дней, пропущенные за 7).
2. **Очки** = w1·вкус + w2·повод + w3·настроение + w4·кухня + w5·наличие продуктов + w6·сезон + w7·свежесть (давно не готовили) + w8·время приготовления. Веса в одном конфиге, значения по умолчанию записать в тестах.
3. **Разнообразие:** MMR-отбор, не больше 2 блюд одного раздела подряд в ленте.
4. **Исследование:** 15% мест отдать блюдам вне профиля, помечать «Попробуйте новое».
5. **Объяснение:** у каждой карточки причина одной фразой («Скоро Масленица», «Вы любите грибы», «Всё есть дома»), строится по шаблонам из самого весомого слагаемого, без ИИ.
Тесты: аллерген никогда не попадает; повтор не вылезает в окне; разнообразие; детерминизм; холодный старт; качество на синтетических профилях (мясоед, вегетарианка, сладкоежка).

## R7-06. Источники блюд для ленты
- Основной: каталог (seed + принятые рецепты).
- Если подходящих меньше N для ленты, `AiRouter` генерирует недостающие блюда по контексту (праздник, кухня, настроение), результат валидируется, кэшируется в базе с `source=ai` и тегами. Запрос короткий, max_tokens из AiMaxTokens, при сбое лента всё равно показывается из каталога без ошибок.
- Оффлайн ИИ не нужен: лента обязана работать полностью без сети и без ПК.

## R7-07. Экран «Лента» (senior-ux)
- Главный экран: вверху лента «Может понравиться» (до 5 крупных карточек с фото-плейсхолдером, названием, временем, причиной).
- Ниже до 4 лент: «К празднику / На сегодня» (только если есть повод), «По настроению» (5 крупных кнопок-настроений), «Кухни мира» (кнопки стран), «Из того, что есть дома».
- Кнопка «Разделы» открывает сетку из 11 разделов с иконками и счётчиком блюд; внутри раздела фильтры-чипы по диете (вегетарианское, малокалорийное, постное и т. д.). Не больше одного ряда чипов.
- На карточке: «Приготовить» и «Не хочу такое» (второе сразу пишет событие и заменяет карточку).
- Размеры шрифтов и целей нажатия по скиллу senior-ux, тест на переполнение при 360dp и шрифте 2.0x для каждого нового экрана (добавить в overflow_all_screens_test).

## R7-08. Календарь и история

- Приготовленное пишет feed_event и попадает в историю, влияет на профиль.

## R7-09. Недостающие продукты и доставка
