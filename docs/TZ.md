# ТЗ: мобильное приложение «Что приготовить?»

Версия от 2026-11-04. Живой оригинал: https://claude.ai/artifact/3q34dtW9VRUsfcDMQSbVxK (при расхождении с этим файлом — спросить владельца).

## 0. Задача для нейросети-исполнителя

Ты — ведущий разработчик. Нужно построить **«Что приготовить?»** — мобильное приложение для Android (iOS — задел). Пользователь отмечает продукты, которые есть дома, и получает блюда, которые из них можно приготовить. У каждого блюда есть тип, сложность, рецепт и пошаговая инструкция. Встроенный ИИ придумывает новые блюда, не даёт им повторяться и подстраивается под вкусы пользователя. Есть календарь блюд на месяц и история приготовленного.

Система — одна программа, которую ты пишешь с нуля:

1. **App** — приложение Flutter. Все данные хранятся на телефоне, сервера у проекта нет.
2. **ИИ-провайдер** — два режима. Если домашний ПК в сети и приложение его нашло — LM Studio на ПК; иначе — GigaChat через интернет. Приложение работает с ними через один интерфейс `AiProvider` (раздел 6). Без ИИ приложение тоже работает — на встроенном каталоге рецептов.

Как работать с этим документом:

- Читай его целиком до первой строки кода. Разделы 2–9 — обязательная спецификация, раздел 10 — порядок работы, раздел 11 — как проверять.
- Двигайся по этапам из раздела 10. После каждого этапа — рабочий, запускаемый результат и короткий отчёт: что сделано, как запустить, что не готово.
- **Этап не засчитывается, пока к отчёту не приложен вывод** `flutter analyze` и `flutter test`, выполненных после последней правки, и скриншот с телефона или эмулятора.
- Не выдумывай API провайдеров ИИ и пакетов. Если нужен эндпоинт или параметр, сверься с официальной документацией и укажи ссылку в отчёте.
- Неясное место — не угадывай молча: выбери самый простой вариант, пометь его `// ASSUMPTION:` в коде и вынеси в отчёт.
- Код, идентификаторы и комментарии — на английском. Интерфейс приложения — на русском (с заделом под i18n через `flutter_localizations` и ARB-файлы).

## 1. Контекст и ограничения

Главное: приложение должно за пару нажатий отвечать на вопрос «что приготовить сегодня из того, что есть». Сейчас этот вопрос бабушка задаёт всей семье.

Пользователи:

| Кто | Что делает | Что это значит для проекта |
| --- | --- | --- |
| Бабушка (основной пользователь) | Отмечает продукты, выбирает блюдо, готовит по шагам, ставит оценку | Крупный шрифт и кнопки, минимум текста, голосовой ввод, никаких регистраций и настроек на старте |
| Внук (администратор) | Устанавливает приложение, вводит ключ ИИ, задаёт ограничения по еде | Настройки спрятаны в отдельный раздел, бабушка их не видит |

Ключевые требования:

1. Выбор продуктов из справочника (с поиском, категориями и голосом) → список блюд, которые можно приготовить.
2. Классификация блюд по типу (суп, второе, салат, гарнир, выпечка, десерт, завтрак, закуска, напиток) и по сложности (легко / средне / сложно), фильтры по обоим.
3. Карточка рецепта: ингредиенты с количеством, время, порции, пошаговая инструкция и режим готовки с таймерами.
4. ИИ придумывает блюда и рецепты, не повторяет недавно приготовленное и учитывает предпочтения.
5. Календарь: блюдо на каждый день месяца, составленное по предпочтениям прошлых дней.
6. История: список приготовленных блюд по дням, с оценками и заметками.

Важное про «обучение» ИИ: модель не дообучается. Приложение само ведёт профиль вкусов (оценки, история, отказы) и передаёт его в каждый запрос, а ещё пересортировывает ответы ИИ локально (раздел 6.4). Для пользователя это выглядит как «приложение запомнило, что мне нравится».

Ограничения:

- Интернет есть не всегда. Без сети работают подбор по каталогу, сохранённые рецепты, календарь и история.
- ИИ может ошибаться в рецептах (температуры, время, пропорции). Ответы проходят проверку (раздел 9).
- Запросы к ИИ стоят денег или ресурсов ПК. Ответы кэшируются, рецепты сохраняются в базу и переиспользуются.

## 2. Архитектура

Приложение автономно: экраны, логика и база живут на телефоне. ИИ — внешний сервис, который можно выключить без потери основных функций.

```
┌──────────── Телефон: приложение Flutter ────────────┐      ИИ-провайдеры
│  Экраны: Сегодня · Что есть дома · Блюда и рецепт   │
│          · Календарь · История                      │   ┌─────────────────────┐
│        │              │               │             │ ┌▶│ LM Studio на ПК     │
│        ▼              ▼               ▼             │ │ │ основной, если найден│
│  Движок подбора   Планировщик    ИИ-сервис ─────────┼─┤ └─────────────────────┘
│  (раздел 5)       (раздел 8)     промпты, валидатор,│ │ ┌─────────────────────┐
│        │              │          выбор ПК/GigaChat  │ └▶│ GigaChat API        │
│        ▼              ▼               ▼             │   │ запасной, интернет  │
│  Локальная база SQLite (drift): продукты · рецепты  │   └─────────────────────┘
│  · история · план · профиль вкусов · кэш ИИ         │
└─────────────────────────────────────────────────────┘
```

Экраны обращаются к трём сервисам, а те — к локальной базе. Наружу ходит только ИИ-сервис, через интерфейс `AiProvider`.

Как проходит запрос «Показать блюда»:

1. Экран отдаёт список отмеченных продуктов и фильтры движку подбора.
2. Движок подбора сразу возвращает локальные рецепты из базы (раздел 5).
3. Параллельно ИИ-сервис собирает промпт: продукты, профиль вкусов, список «не предлагать» (раздел 6).
4. Ответ ИИ проходит валидатор (раздел 9) и проверку на дубли; новые рецепты сохраняются в базу.
5. Экран добавляет новые карточки сверху. Если ИИ не ответил за 30 с, остаются только локальные варианты.

## 4. Модель данных

Все данные — в одной SQLite-базе на телефоне. У каждой таблицы: `id` (UUID v4), `created_at`, `updated_at`, `deleted_at` (мягкое удаление). Это задел под будущую синхронизацию с семьёй.

### 4.1. Таблицы

| Таблица | Ключевые поля | Назначение |
| --- | --- | --- |
| `ingredients` | `name`, `synonyms` (JSON-массив), `category`, `is_staple`, `icon` | Справочник продуктов. `category`: овощи, мясо, рыба, молочное, крупы, бакалея, фрукты, специи… `is_staple` = «всегда есть» (соль, вода, подсолнечное масло, сахар, перец) |
| `pantry_items` | `ingredient_id`, `is_available`, `updated_at` | Что сейчас есть дома. Количество не храним: бабушка отмечает только «есть / нет» |
| `recipes` | `title`, `normalized_title`, `dish_type`, `difficulty`, `cuisine`, `total_minutes`, `active_minutes`, `servings`, `description`, `source` (`seed` / `ai` / `user`), `fingerprint`, `ai_model`, `is_favorite` | Блюдо. `dish_type` и `difficulty` — перечисления (4.2). `fingerprint` — для антиповторов (6.3) |
| `recipe_ingredients` | `recipe_id`, `ingredient_id`, `amount`, `unit`, `is_optional`, `note` | Состав. `unit`: г, кг, мл, л, шт, ст. л., ч. л., стакан, по вкусу |
| `recipe_steps` | `recipe_id`, `position`, `text`, `timer_seconds`, `tip` | Пошаговая инструкция. Шаг с ожиданием имеет таймер |
| `cooked_entries` | `recipe_id`, `cooked_on` (дата), `rating` (1–5, можно пусто), `would_repeat`, `note` | История приготовленного |
| `meal_plan_entries` | `date`, `recipe_id`, `meal_slot` (по умолчанию `main`), `status` (`planned` / `cooked` / `skipped`), `locked` | Календарь. `locked` — день, закреплённый вручную; пересборка плана его не трогает |
| `feedback_events` | `recipe_id`, `kind` (`liked`, `disliked`, `skipped`, `cooked`, `opened`, `rejected_suggestion`), `reason`, `at` | Сырые сигналы для профиля вкусов |
| `preference_profile` | одна строка: `dish_type_weights`, `ingredient_weights`, `cuisine_weights`, `difficulty_weights` (JSON), `excluded_ingredients`, `allergies`, `max_total_minutes`, `servings_default` | Профиль, пересчитываемый из `feedback_events` (6.4) |
| `ai_requests` | `kind`, `prompt_hash`, `response_json`, `model`, `tokens_in`, `tokens_out`, `status`, `at` | Кэш и журнал запросов к ИИ |

### 4.2. Перечисления

- `DishType`: `soup` (суп), `main` (второе), `side` (гарнир), `salad` (салат), `breakfast` (завтрак), `snack` (закуска), `baking` (выпечка), `dessert` (десерт), `drink` (напиток), `preserve` (заготовки).
- `Difficulty`: `easy` — до 5 шагов и до 30 мин активной работы; `medium` — до 10 шагов или до 60 мин; `hard` — всё остальное, а также тесто или несколько одновременных процессов. ИИ предлагает сложность, но итог считает приложение по этим правилам (`// ASSUMPTION:`, если сдвинешь пороги).

### 4.3. Стартовые данные

- `ingredients.json`: не менее 250 продуктов домашней кухни с синонимами и разговорными формами («картошка» = «картофель», «фарш», «куриное филе» → «курица» как родитель).
- `recipes.json`: не менее 120 рецептов русской и домашней кухни, все типы и сложности. Каталог можно сгенерировать ИИ один раз скриптом `tool/gen_seed.dart`, но перед коммитом он проходит тот же валидатор, что и ответы ИИ (раздел 9), и выборочную проверку человеком.

## 5. Подбор блюд

Подбор идёт в два потока: мгновенно из локальной базы и параллельно через ИИ. Локальные варианты показываются сразу, а новые блюда от ИИ добавляются сверху с пометкой «Новое», когда придут.

### 5.1. Нормализация продуктов

1. Ввод (текст или голос) разбивается по запятым и слову «и».
2. Каждое слово: нижний регистр, ё→е, убрать окончания простым стеммером для русского.
3. Поиск по `name` и `synonyms` в FTS5, затем нечёткое сравнение (расстояние Левенштейна ≤ 2) для опечаток.
4. Не нашлось — показать «Добавить «…» как новый продукт». Новые продукты от ИИ проходят тот же путь и не дублируют справочник.

### 5.2. Совпадение рецепта с продуктами

Для каждого рецепта считаем по обязательным ингредиентам (без `is_staple` и `is_optional`):

- `missing` — сколько не хватает. Учитывает иерархию: есть «куриное филе» — значит есть «курица».
- `coverage` = есть / всего обязательных.

Рецепты делятся на две группы: **«Можно приготовить сейчас»** (`missing = 0`) и **«Не хватает 1–2 продуктов»** (недостающее перечислено на карточке). Остальные не показываются.

### 5.3. Ранжирование

Внутри группы сортируем по итоговому баллу:

```latex
score = 0.35 \cdot coverage + 0.30 \cdot taste + 0.20 \cdot novelty + 0.10 \cdot fit + 0.05 \cdot explore
```

| Слагаемое | Как считается (всё в диапазоне 0–1) |
| --- | --- |
| `coverage` | Доля имеющихся обязательных ингредиентов (5.2) |
| `taste` | Среднее весов профиля по типу блюда, кухне и ингредиентам (6.4), либо собственная оценка блюда, если его уже готовили |
| `novelty` | 0, если блюдо готовили за последние 7 дней; далее линейно растёт до 1 к 30-му дню. Похожие блюда (6.3) штрафуются вдвое меньше |
| `fit` | 1, если время и сложность в пределах профиля; иначе пропорционально снижается |
| `explore` | Случайная добавка с фиксированным зерном на день, чтобы в топ иногда попадало неожиданное |

Жёсткие фильтры применяются до скоринга: аллергены и исключённые продукты убирают рецепт полностью, фильтры по типу и сложности — тоже. Веса формулы вынеси в константы `ScoringWeights` и покрой тестами с фиксированными данными.

### 5.4. Разнообразие выдачи

В первых 10 карточках не больше 3 блюд одного типа и не больше 2 с одним главным ингредиентом. Реализуй жадным переупорядочиванием (вроде MMR), если нет фильтра по типу.

## 6. ИИ: генерация, антиповторы и предпочтения

ИИ делает три вещи: предлагает новые блюда из имеющихся продуктов, пишет полный рецепт и составляет план на месяц. Решения о сортировке, фильтрах и повторах принимает код приложения, а не модель.

### 6.1. Провайдеры

Интерфейс один:

```
abstract class AiProvider {
  Future<Map<String, dynamic>> completeJson({
    required String system,
    required String user,
    required Map<String, dynamic> jsonSchema,
    Duration timeout,
  });
  Future<bool> healthCheck();
}
```

| Адаптер | Куда ходит | Когда используется |
| --- | --- | --- |
| `LmStudioProvider` (основной) | `http://<IP ПК>:1234/v1/chat/completions`, OpenAI-совместимый API; `response_format` с `json_schema` поддерживается ([документация](https://lmstudio.ai/docs/developer/openai-compat/structured-output)) | ПК найден в локальной сети и отвечает. Бесплатно и без лимитов |
| `GigaChatProvider` (запасной) | Токен: `POST https://ngw.devices.sberbank.ru:9443/api/v2/oauth`, заголовки `Authorization: Basic <ключ>`, `RqUID: <uuid4>`, тело `scope=GIGACHAT_API_PERS`; токен живёт 30 мин ([документация](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api)). Чат: `POST <base>/api/v1/chat/completions` с `Bearer <токен>` | ПК не найден или упал во время запроса. Freemium для физлиц: 250 млн токенов Lite в год, один поток |
| `FakeAiProvider` | — | Тесты и демо, отдаёт JSON из `test/fixtures` |

Уточнения по GigaChat: базовый адрес вынеси в настройку — в документации сказано, что старый адрес `https://gigachat.devices.sberbank.ru` остаётся для подключившихся до 17 июля 2026, сверь актуальный. Сертификат «Russian Trusted Root CA» положи в `assets/certs/` и доверяй ему **только** в отдельном `Dio` для хостов Сбера. Строгий JSON-режим у GigaChat не гарантирован — схема идёт в системный промпт, ответ проходит валидатор.

### 6.1.1. Выбор провайдера (`AiRouter`)

1. **Поиск ПК.** В настройках кнопка «Найти компьютер»: параллельный опрос подсети /24 телефона на порту 1234 (`GET /v1/models`, таймаут 300 мс, до 32 запросов одновременно). Найденный адрес сохраняется. Есть ручной ввод адреса.
2. **Проверка перед запросом.** Телефон в Wi-Fi (`connectivity_plus`) и последняя успешная проверка была меньше 60 с назад — сразу LM Studio. Иначе `GET http://<ПК>:1234/v1/models` с таймаутом 1,5 с: ответ 200 и в списке есть выбранная модель — LM Studio, иначе GigaChat.
3. **Смена адреса.** ПК не отвечает по сохранённому адресу — фоновый повторный поиск по подсети, не чаще раза в час (роутер мог выдать ПК новый IP).
4. **Отказ посреди запроса.** Ошибка соединения или таймаут LM Studio — тот же запрос сразу уходит в GigaChat, ПК помечается недоступным на 60 с. Невалидный JSON — один повтор на том же провайдере, затем GigaChat.
5. **Нет ни того, ни другого** — только локальные варианты, без сообщения об ошибке.
6. **Таймауты LM Studio** больше, чем у облака: подборка 60 с, рецепт 90 с, неделя плана 180 с.
7. **Индикатор.** В настройках и мелко на экране «Блюда»: «Помощник: домашний ПК» / «Помощник: GigaChat» / «Без помощника».

Настройка на ПК (идёт в `docs/INSTALL.md`): в LM Studio вкладка Developer → сервер включён, «Serve on Local Network» включено, модель загружена; правило брандмауэра Windows на TCP 1234 для профиля «Частная»; сеть Wi-Fi в Windows — «Частная». Модель — instruct от 7B, которая держит структурированный вывод: модели меньше 7B с ним часто не справляются.

Расход: одна подборка + один полный рецепт — порядка 5–10 тыс. токенов (оценка, измерь на этапе 3). GigaChat нужен только когда ПК выключен, так что бесплатного лимита хватит с большим запасом. В настройках показывай счётчик токенов GigaChat за месяц из `ai_requests` (поле `model` хранит, какой провайдер ответил).

### 6.2. Запросы и JSON-схемы

Каждый запрос просит строгий JSON. Если провайдер поддерживает `response_format` со схемой — передавай её; если нет — схема идёт в текст системного промпта. Невалидный ответ — один повтор с текстом ошибки валидатора, затем тихий отказ (показываем только локальные варианты).

| Запрос | Вход | Выход |
| --- | --- | --- |
| `suggest_dishes` | Список продуктов в наличии, фильтры типа и сложности, сжатый профиль вкусов, список «не предлагать» (6.3) | 5–8 карточек: `title`, `dish_type`, `difficulty`, `total_minutes`, `main_ingredients[]`, `missing[]`, `why` (одна фраза «почему вам понравится») |
| `full_recipe` | Карточка из `suggest_dishes`, число порций | Рецепт по схеме таблиц `recipes` + `recipe_ingredients` + `recipe_steps` (шаг ≤ 2 предложений, `timer_seconds` для ждущих шагов) |
| `month_plan` | Диапазон дат (не больше 7 дней за запрос), история за 30 дней, профиль, закреплённые дни, правила чередования (8.1) | Массив `{date, title, dish_type, difficulty, main_ingredients[]}`. Полный рецепт догенерируется при открытии дня |

Системный промпт (основа, дополняй по запросу):

```
Ты — опытный повар домашней кухни. Советуешь блюда из продуктов,
которые есть у человека. Правила:
- Только реальные, проверенные блюда; без экзотических продуктов.
- Используй продукты из списка «есть»; соль, вода, масло, сахар, перец считаются
  имеющимися. Недостающее — не больше 2 продуктов, перечисли в missing.
- Никогда не предлагай блюда из списка «не предлагать» и их вариации.
- Никогда не используй аллергены и исключённые продукты.
- Указывай безопасные температуры и время для мяса, птицы, рыбы и яиц.
- Пиши просто, как для пожилого человека: короткие шаги, без жаргона.
- Отвечай только JSON по схеме, без текста вокруг.
```

### 6.3. Антиповторы

Повтор ловим дважды: до запроса (чтобы ИИ его не предложил) и после (чтобы отсечь, если всё же предложил).

1. **Список «не предлагать»** в промпте: названия блюд за последние 14 дней истории, блюда с оценкой ≤ 2 и отклонённые подсказки за 7 дней. Не больше 40 названий.
2. **Отпечаток блюда** (`fingerprint`): `dish_type` + отсортированные нормализованные id главных ингредиентов (до 4).
3. **Проверка похожести** нового блюда с уже сохранёнными: дубль, если совпал `normalized_title` или коэффициент Жаккара по ингредиентам ≥ 0.8 при том же `dish_type`. Дубль не сохраняется как новый рецепт: используется существующий, и на него действует `novelty` из 5.3.
4. **Кэш**: одинаковый набор продуктов + фильтры в тот же день — ответ из `ai_requests`, не новый запрос. Кнопка «Другие варианты» добавляет уже показанные блюда в «не предлагать» и делает новый запрос.

### 6.4. Обучение на предпочтениях

Профиль — это веса от −1 до +1 по типу блюда, сложности, кухне и каждому ингредиенту. Пересчёт — после каждого события в `feedback_events`.

| Событие | Сигнал |
| --- | --- |
| Приготовила, оценка 5 | +1.0 |
| Оценка 4 | +0.5 |
| Приготовила без оценки | +0.3 |
| Оценка 3 | 0 |
| Оценка 1–2 или «больше не предлагать» | −1.0 |
| Пропустила день в календаре | −0.2 |
| Смахнула подсказку «не хочу» | −0.3 |

Сигнал распределяется на признаки блюда (тип, сложность, кухня, главные ингредиенты). Вес признака — экспоненциально затухающее среднее с полураспадом 60 дней, чтобы старые вкусы постепенно забывались:

```latex
w_f = \frac{\sum_i s_i \cdot 2^{-\Delta t_i / 60}}{\sum_i 2^{-\Delta t_i / 60} + 3}
```

Слагаемое 3 в знаменателе держит вес у нуля, пока сигналов мало. В промпт уходит сжатое описание профиля: топ-5 любимых и топ-5 нелюбимых признаков + 5 лучше оценённых блюд («в духе этих»). В настройках есть экран «Что приложение знает о ваших вкусах» с этим же списком и кнопкой «Сбросить».

## 7. Экраны и UX

Интерфейс делается под пожилого человека: четыре вкладки, крупные кнопки и ни одного обязательного шага настройки.

### 7.1. Правила доступности

- Базовый шрифт 18 sp, заголовки 24 sp; приложение уважает системный масштаб шрифта и не ломается при 200%.
- Зона нажатия ≥ 56 dp, контраст текста ≥ 4.5:1 (WCAG AA).
- Никаких жестов без дублирующей кнопки; свайп не единственный способ.
- Понятные слова вместо иконок: у каждой иконки есть подпись.
- Ошибки — человеческим языком: «Нет интернета, показываю сохранённые рецепты», без кодов и английских слов.
- Светлая тема по умолчанию, тёмная — по системной настройке.

### 7.2. Экраны

| Экран | Что на нём | Главное действие |
| --- | --- | --- |
| **Сегодня** (главный) | Блюдо дня из календаря крупной карточкой + кнопка «Подобрать из того, что есть» | «Готовить» / «Другое блюдо» |
| **Что есть дома** | Поиск + кнопка микрофона; продукты по категориям плитками с иконкой; выбранные подсвечены; блок «Часто выбираете» сверху | «Показать блюда (N)» — счётчик обновляется сразу |
| **Блюда** (результат подбора) | Чипы-фильтры по типу и сложности; две группы (5.2); карточка: название, тип, сложность (1–3 колпачка), время, «не хватает: …», пометка «Новое» | Открыть рецепт; «Не хочу» на карточке |
| **Рецепт** | Порции (± пересчитывают количества), ингредиенты с галочками «есть», шаги списком, советы | «Начать готовить», «В избранное», «Поставить в календарь» |
| **Режим готовки** | Один шаг на экран, очень крупный текст (28 sp), большие кнопки «Назад» / «Дальше», таймер со стартом одним нажатием, экран не гаснет; опция «Прочитать вслух» (системный TTS) | На последнем шаге — «Готово!» → оценка звёздами → запись в историю |
| **Календарь** | Сетка месяца; в дне — иконка типа блюда и статус (запланировано / приготовлено / пропущено); под сеткой — блюдо выбранного дня | «Заменить», «Закрепить», «Составить план на месяц» |
| **История** | Список по дням (новые сверху), оценка, заметка; фильтр по месяцу и типу; поиск | «Приготовить снова», изменить оценку |
| **Настройки** (под долгим нажатием на заголовок или PIN) | ИИ-провайдер и ключ, «Проверить связь», аллергии и исключения, порции по умолчанию, профиль вкусов, резервная копия JSON, счётчик токенов | — |

Нижняя панель: **Сегодня · Что есть дома · Календарь · История**. Настройки в панель не выносятся, чтобы бабушка случайно их не сбила.

### 7.3. Уведомления

Одно уведомление в день в выбранное время (по умолчанию 10:00): «Сегодня по плану: борщ». Нажатие открывает рецепт. Включается в настройках, по умолчанию выключено.

## 8. Календарь и история

Календарь планирует вперёд, история хранит факт. История — главный источник данных для следующего плана.

### 8.1. План на месяц

- По кнопке «Составить план» заполняются все дни от сегодня до конца месяца, кроме закреплённых. 1-го числа приложение предлагает составить план на новый месяц.
- Генерация идёт неделями (до 7 дней за запрос), чтобы влезать в контекст небольших моделей. Каждая следующая неделя получает предыдущую как часть «не повторять».
- Правила чередования, которые проверяет код после ответа ИИ:
  - одно блюдо — не чаще раза в 14 дней (любимые с оценкой 5 — раз в 10 дней);
  - один главный ингредиент — не больше 2 дней подряд;
  - суп — не меньше 2 раз в неделю, если профиль не говорит обратного;
  - сложные блюда — не больше 2 в неделю и не в два дня подряд;
  - доля типов блюд примерно соответствует весам профиля.
- Нарушение правила — день заменяется лучшим подходящим блюдом из локальной базы (скоринг 5.3 без `coverage`). Без ИИ весь план составляется так же, из базы.
- План не привязан к продуктам в наличии. При открытии дня показывается «не хватает: …» и кнопка «Заменить на то, что можно из имеющегося».
- День в прошлом со статусом `planned` после полуночи переходит в `skipped` и даёт сигнал −0.2 (6.4). Если бабушка приготовила другое — она добавляет его в историю, и день помечается `cooked` с фактическим блюдом.

### 8.2. История

- Запись появляется тремя путями: «Готово!» в режиме готовки, отметка в календаре, ручное добавление (в том числе блюда, которого нет в базе: тогда создаётся рецепт с `source = user`).
- Одно блюдо в день по умолчанию, но можно добавить несколько.
- История не удаляется автоматически. Удаление записи — мягкое, с кнопкой «Отменить» 5 секунд.
- Наверху экрана — короткая сводка за месяц: сколько блюд приготовлено, сколько новых, самое высокооценённое.
- Экспорт и импорт всей базы в JSON (настройки → «Резервная копия»), чтобы история не пропала при смене телефона.

## 9. Безопасность, офлайн-режим и приватность

Главный риск — не взлом, а неверный рецепт от ИИ: недожаренная курица или аллерген в составе. Поэтому каждый ответ ИИ проходит валидатор `RecipeValidator` до сохранения.

### 9.1. Проверки валидатора

| Проверка | Действие при нарушении |
| --- | --- |
| JSON соответствует схеме, перечисления из списка 4.2 | Повтор запроса с текстом ошибки, затем отказ |
| В составе нет аллергенов и исключённых продуктов (с учётом синонимов и дочерних продуктов) | Рецепт отбрасывается без повтора |
| Есть хотя бы 2 шага, сумма таймеров ≤ `total_minutes` + 10% | Повтор |
| Для мяса, птицы, фарша, рыбы, яиц есть шаг тепловой обработки с временем не ниже табличного минимума (таблица в `core/ai/safety_minimums.dart`) | Повтор; после второго раза — отказ |
| Количества в разумных пределах на порцию (соль ≤ 10 г, масло ≤ 50 мл и т. п.) | Пометка «проверьте количество» у ингредиента |
| Нет несъедобных и опасных «ингредиентов» (стоп-список) | Отказ |

На карточке рецепта от ИИ — ненавязчивая подпись «Рецепт придуман помощником. Проверяйте готовность мяса и рыбы».

### 9.2. Офлайн

- Приложение стартует и работает без сети: все экраны, подбор по базе, календарь, история.
- Запросы к ИИ — с таймаутом 30 с (план — 90 с), не блокируют интерфейс, отменяются при уходе с экрана.
- Сохранённый рецепт от ИИ доступен навсегда, без повторных запросов.

### 9.3. Приватность и ключи

- Ключ ИИ — только в `flutter_secure_storage`, не в коде, не в логах, не в резервной копии. В репозитории — `.env.example` без значений.
- В ИИ уходят только продукты, названия блюд и обезличенные веса вкусов. Имена, заметки из истории и данные устройства не отправляются.
- К LM Studio на ПК — только в домашней сети. Для `http://` разреши cleartext только для частных адресов через `network_security_config.xml`, а не глобально.
- Настройки закрыты 4-значным PIN (необязательно), чтобы их не сбили случайно.

## 11. Критерии приёмки и сценарии проверки

Приложение принято, когда шесть сценариев ниже проходят на реальном Android-телефоне, а `flutter analyze` без замечаний и `flutter test` зелёный.

**Сценарий 1. «Что приготовить сейчас» (сеть выключена).**

1. На вкладке «Что есть дома» сказать голосом: «картошка, лук, яйца, молоко».
2. Нажать «Показать блюда», выбрать фильтр «Завтрак» + «Легко».
3. Ожидаемо: все 4 продукта распознаны; в группе «Можно сейчас» есть хотя бы одно блюдо (например, омлет); список появился менее чем за 1 с; нет сообщений об ошибке.

**Сценарий 2. Новое блюдо от ИИ и готовка.**

1. ИИ настроен, сеть включена. Отметить «курица, рис, морковь, лук».
2. Дождаться карточек «Новое», открыть одну, изменить порции с 2 на 4.
3. Пройти режим готовки, запустить таймер, свернуть приложение, дождаться сигнала.
4. Нажать «Готово!», поставить 5.
5. Ожидаемо: количества удвоились; есть шаг тепловой обработки курицы; запись в истории с сегодняшней датой и оценкой 5; рецепт открывается и без сети.

**Сценарий 3. Без повторов.**

1. После сценария 2 на следующий день (дату можно подменить через отладочный флаг) отметить те же продукты.
2. Ожидаемо: вчерашнего блюда нет в первой десятке, ИИ не предложил его и его вариации (проверить по `ai_requests`); кнопка «Другие варианты» даёт новые блюда, не повторяющие показанные.

**Сценарий 4. Календарь.**

1. Закрепить на ближайшую субботу блюдо из избранного, нажать «Составить план на месяц».
2. Заменить один день кнопкой «Заменить».
3. Ожидаемо: заполнены все дни до конца месяца; суббота не изменилась; все правила 8.1 соблюдены (сверить тестом на выгруженном плане); экран «Сегодня» показывает блюдо из плана. То же с выключенным ИИ — план строится из локальной базы.

**Сценарий 5. Безопасность и вкусы.**

1. В настройках добавить аллергию «орехи» и исключить «грибы». Поставить 1 любому десерту из истории.
2. Запросить десерты и план на неделю.
3. Ожидаемо: ни в одном показанном рецепте нет орехов и грибов (включая «грецкие орехи», «шампиньоны»); десерт с оценкой 1 не появляется; в экране «Что приложение знает о ваших вкусах» десерты спустились вниз.

**Сценарий 6. Переключение ПК ↔ GigaChat.**

1. ПК включён, LM Studio запущен. В настройках нажать «Найти компьютер» — адрес найден за ≤ 10 с, индикатор «домашний ПК».
2. Запросить блюда: в `ai_requests` провайдер LM Studio.
3. Закрыть LM Studio и сразу запросить снова: ответ приходит от GigaChat, без ошибки на экране, индикатор «GigaChat».
4. Запустить LM Studio, подождать 60 с, запросить: снова LM Studio.
5. Выйти из домашнего Wi-Fi (мобильный интернет): GigaChat без попытки достучаться до ПК.
