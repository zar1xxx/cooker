## Порядок работ
1. **R10-01.** Составить список добавляемых продуктов по таблице: `id` (латиница), русское название, синонимы и падежи, категория, `parent_id`, `is_staple`, единицы измерения. Источник — проверенные справочники; без выдумывания.
2. **R10-02.** Проверить конфликты: дубли с существующими id и названиями, совпадения синонимов, склонения для распознавания в тексте (`tool/py` и `validate_seed`).
3. **R10-03.** Добавить аллергены и тепловые требования для новых продуктов (мясо, рыба, грибы, яйца, бобовые) — это нужно `RecipeValidator`.
4. **R10-04.** Обновить правила калорийности (ккал/100 г) и единицы измерения для новых продуктов.
5. **R10-05.** Написать новые рецепты (≥ 2 на каждый новый продукт) тем же рукописным способом, что в R9, с проверкой валидатором.
6. **R10-06.** Обновить подбор: поиск продуктов в UI должен справляться с ~800 позициями (категории, быстрый поиск, подсказки), крупный шрифт для пожилого пользователя сохраняется.
7. **R10-07.** Миграция drift: новые продукты попадают в базу при обновлении приложения без потери данных пользователя (холодильник, избранное).
8. **R10-08.** `tool\format.bat`, `tool\run_check.bat`, тесты seed (`validate_seed`, `seed_quality`), отчёт.

## Критерии приёмки
- Продуктов не меньше 700, у каждого есть категория, синонимы и единицы измерения.
- Нет дублей id и названий; все `parent_id` существуют.
- Для каждого нового мяса, рыбы, птицы, грибов, яиц и бобовых есть правила тепловой обработки.
- Новых рецептов не меньше 300; все проходят `RecipeValidator` и lint.
- Все тесты проходят; поиск по продуктам остаётся быстрым.

## Порядок относительно R9
R10 запускается после переписывания шаблонных рецептов (R9), чтобы не переписывать новые рецепты дважды. Планирование R10-01 и R10-02 можно делать параллельно.
