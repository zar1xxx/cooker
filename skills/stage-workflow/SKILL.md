# Работа по этапам

## Начало сессии

1. Прочитай `docs/STATUS.md` — текущий этап, блокеры, ответы владельца на вопросы.
2. Открой `docs/TASKS.md`, найди первую незакрытую задачу текущего этапа.
3. Прочитай разделы ТЗ, на которые ссылается задача. Не полагайся на память о прошлых сессиях — перечитай.
4. Открой нужные скиллы (таблица в `AGENTS.md`).

## Выполнение задачи

1. Напиши тест, который проверяет поведение из задачи (для логики — до кода; для UI — виджет-тест после).
2. Реализуй минимально, чтобы тест прошёл.
3. Запусти `powershell -ExecutionPolicy Bypass -File tool\check.ps1`.
4. Красное → чини. Две неудачные попытки одной и той же правки → блокер в `docs/STATUS.md`, переходи к другой задаче.
5. Зелёное → `[x]` в `docs/TASKS.md`, строка в журнал `docs/STATUS.md`, коммит `S<N>-<NN>: <что сделано>`.

## Закрытие этапа

1. Все задачи этапа `[x]`.
2. Пройди условие «Готово, когда» руками на эмуляторе или телефоне. Сделай скриншоты в `docs/reports/img/`.
3. Запусти `tool\check.ps1` **последним действием** перед отчётом.
4. Заполни `docs/reports/STAGE_<N>.md` по `docs/REPORT_TEMPLATE.md`. Вывод проверок вставляй целиком, не пересказом.
5. Обнови «Сейчас» в `docs/STATUS.md`: следующий этап.

## Честность отчёта

- Отмечай в «Готово, когда» только проверенное тобой. Собрал APK, но не ставил на телефон — пиши «APK собран; установку проверяет владелец» и добавь пункт в `docs/STATUS.md` → «Проверить владельцу на устройстве».
- Нет эмулятора — так и напиши; виджет-тест не заменяет проверку на устройстве, но засчитывается как частичная.

## Чего не делать

- Не отмечать `[x]` по принципу «код написан». Только «проверено».
- Не переходить на следующий этап с красными тестами.
- Не удалять и не ослаблять тесты, чтобы стало зелёным. Если тест неверен — исправь его и объясни в отчёте почему.
- Не трогать задачи будущих этапов «заодно».
